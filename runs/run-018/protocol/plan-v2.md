# Protocol v2: explicit separation from training labels

This amendment is fixed before any model fitting, similarity matching or water-regime agreement result. It supplements v1, whose full text and commit remain unchanged. Source acquisition and all feature, method and primary-outcome definitions from v1 remain in force unless specified here. Motivation: code/design inspection identified that disjoint 4km blocks do not by themselves ensure a minimum distance between training and held-out polygons at their edges.

For each rotation, first assign query, reference and nominal training roles exactly as in v1. Remove from the **training role** any wetland whose selected interior point is within **1km of any query or reference point in the same window**, regardless of vegetation subclass. Do not alter query/reference roles or their pools based on this removal. Save nominal and retained training IDs and nearest held-out distance. Training-pair minimum separation remains 1km. All learned transformations, scaling, imputations, centring, whitening, classifier fits and training priors use only the retained training wetlands. No water-regime labels participate in this buffer decision.

The primary query-to-reference buffer remains 1km. For the planned 0km and 3km candidate-pool sensitivity, keep the same primary retained training set so these compare reference-pool restrictions alone. Add a planned conservative **3km training-to-held-out buffer** sensitivity and the original unbuffered-training analysis as an explicit diagnostic of spatial dependence. These are not independent replications. If a rotation has no retained training observations globally, its learned comparisons fail and are reported; if it lacks one of A/C/F globally, preserve the classes present and assign absent classes zero predicted probability rather than fabricate training examples. If a region has no local retained training points, global learning from the other fixed-panel regions is allowed and the absence is counted.

This correction may reduce fit sample size and changes the main plan before its outputs. It is a prospective design correction, not a response to observed matching performance. The date/event and commit fixing it are in events.jsonl. No scientific human intervention was involved.
