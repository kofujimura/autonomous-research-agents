# Single candidate-critique API plan

Purpose: only the exception in research-question step 6, critique of the five topic candidates. It is not an experimental subject, literature-reading assistant, coding assistant, paper writer or reviewer. No other external models or sub-agents are authorized.

Provider/model/settings: OpenAI Responses API; exactly `gpt-6-astra`; reasoning effort `xhigh`; `background=True`; web-search tool and source inclusion required by the copied skill. Use `client.responses.create`, then `retrieve` while queued/in progress; cancel if abandoning. No output cap, as explicitly required by the skill. At most one generation request; a second is allowed only after the specified failure. SDK automatic retries disabled. Status retrieval is not another generation call.

Why no local model: this is the specifically prescribed critic, not a choice among experimental instruments. The request uses the copied template verbatim, filling only the candidate list, in candidate-ID order. It contains only questions, methods, and closest prior work with differences. It does not contain the author's scores, order of preference or preferred candidate. The scoring file must be committed before sending.

Budget: total research/review API budget USD 20; cumulative actual use before first request USD 0. Standard short-context prices confirmed on 2026-10-27 in saved official `sources/openai-pricing.md` and `sources/openai-gpt-6-astra.md`: input $10/million, cached input $1/million, output (including reasoning) $50/million; web search $0.01/call plus search content input tokens. No token counts are asserted before measurement. Planning estimate is a few dollars, not a bill or guaranteed upper bound. This one critique is explicitly exempt from the pre-call maximum-cost check under the skill. No other API generations are planned. Actual usage and search counts are reconciled from the complete saved response using `code/ai_api.py`.

Terms: official OpenAI Services Agreement effective 2026-01-01, sections 3.3 and 4, checked on 2026-10-27. Only author-created candidate descriptions and public bibliographic details are sent. No personal data, no competing-model training, no bypass of limits or safety measures. Direct curl of the agreement returned 403; the publicly available agreement was read with the web tool. No account credentials were inspected.

Records: all generations go through `code/ai_api.py`. Requests/responses are saved under `experiments/topic-critique/`, with progression records in `api_calls.jsonl`; count unique `call_id` values, using their last entry for settled usage. Do not infer a bill from queued progress records. The key is read only from `FREE_RESEARCH_OPENAI_API_KEY`, never serialized. No new generation after unresolved costs or budget exhaustion.

Analysis: read the completed critique once; independently verify cited sources before using them. Classify each substantive point adopted/not adopted with reasons. Ignore any ranking or proposed new topics as selection grounds. Append any score revisions, preserving initial scores. State this consultation in the eventual paper's limitations. Reproduction of the experiment results must need no further API calls.
