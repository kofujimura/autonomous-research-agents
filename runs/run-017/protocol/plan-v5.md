# Main protocol v5: pre-performance regional-allocation control

This supplements v1–v4, before any mapping model has been fit or scored. The original primary contrast is unchanged. This additional diagnostic tests whether a global object frame changes performance mainly by moving training examples between the four reference regions rather than changing allocation within a region.

Add `area_region` and `object_region` at the primary budget, RF decoder, five original seeds and AEF/optical representations. Allocate the positive and negative half-budgets equally across available training regions. If a half-budget is not divisible by the number of regions, assign its remainder using a seed-dependent permutation of the fixed sorted region IDs; use the same quotas for both classes and policies. At the primary within-region setting the quotas are exactly 250 positive and 250 negative fitting positions per region.

For `area_region`, draw positive positions uniformly within each region's reference-positive pixel pool. For `object_region`, select training components uniformly then pixels uniformly within that region, without replacement, using the original all-size object frame. Draw the same region-balanced negative positions for both policies, with a separate seeded generator. No validation/test labels or object IDs enter selection. Publish realized regional class counts and component coverage. Compute the same representation-by-allocation interaction for these two arms and compare it descriptively with primary H1.

This is a secondary, pre-performance amendment prompted by the design's global positive pools and four heterogeneous reference projects. It is not a replacement primary hypothesis. Execute after the original primary fits and frame/class-composition controls, before lower-priority extensions if resources require prioritization. It does not remove within-region habitat-composition differences or establish causal effects of representation architecture.
