# Main experimental protocol v1

This plan is fixed after topic selection and before any main mapping comparison or main-area predictor retrieval. The selection record, critique response, pilot outcomes and safety check are in topic-selection.md and critic-response.md. All main numbers will be generated from saved inputs and predictions. Any later change will be appended as a new plan version/deviation before dependent execution.

## Research question and scope

How does training-point allocation interact with annual satellite embeddings versus seasonal optical predictors in recovering small **mapped palustrine wetland patches** at a common reference-upland commission-area constraint, and does an allocation benefit require an oracle object sampling frame?

The estimand is agreement with a public, externally produced inventory, not true ecological completeness, legal wetland extent, species habitat quality, human annotation cost or a causal effect of an embedding's internal context. The study evaluates an existing-inventory/sparse-training scenario. Full reference polygons define the evaluation target and the oracle allocation; they are not a free resource in a de novo mapping claim. Predictor/reference pretraining dependencies may exist (e.g. AEF uses NLCD targets). No independent reproduction or independent model evaluation is claimed.

## Planned tests

H1 (primary, two-sided): the oracle object-allocation gain in small-patch recovery differs between AEF and seasonal optical predictors, under the same training-point positions and held-out reference-upland false-positive area rate of 5%. Contrast: (AEF object minus AEF area) minus (optical object minus optical area). Report both component gains, the interaction, and uncertainty; do not equate a sampling gain common to both representations with an embedding-specific effect.

H2 (practical comparison): a candidate-object allocation derived only from training-area imagery and an initial subset of the counted labels improves small-patch recovery relative to area sampling. Compare it also with uncertainty-based sampling and the oracle allocation. A failure to recover the oracle gain is an important negative result.

H3 (sampling/appearance boundary condition): homogeneous-interior sampling and explicit probability-map smoothing change mapped-patch recovery differently from area-based accuracy. No assumption that smoother maps are worse; image smoothness itself is not an accuracy metric.

Primary decoder: random forest. Logistic regression is a planned model-capacity check. Primary training budget: 2,000 total labelled pixel positions. Planned sensitivity budgets: 500 and 8,000, subject to eligible unique positions. Repetitions: five training seeds [101, 202, 303, 404, 505]. Primary sampling/representation contrasts and reference definitions are fixed here, before outcomes.

## Data, provenance, reuse and geography

Required attribution: “The AlphaEarth Foundations Satellite Embedding dataset is produced by Google and Google DeepMind.” Official GCS guide confirms provider-pays access; no authenticated or requester-pays route. The source inventory has omissions, class/boundary errors and varying mapping procedures. Do not call it perfect ground truth. Link per-project supplementary mapping reports; retain all acquisition dates/hashes. Query IDs first and retrieve all IDs in batches not exceeding the documented service limit (500); verify no truncation or duplicate IDs. The P01 truncated query is never used in main evidence.
- Copernicus Sentinel-2 Level-2A public COG scenes through Earth Search, year 2020, free/full/open access and Copernicus attribution. Anonymous public object reads only. Save STAC scene identifiers, processing baseline/scales, original URLs, date and hashes of extracted raw arrays. No cloud account or billing route. Earth Search 2017 access check was selection-only; main year is 2020. Scene processing dates and cloud/no-data fractions are retained.

Four regions are the public reference projects with object IDs 29259 (Prairie Pothole Watersheds 2 NRCS), 29573 (VT Winooski Otter Creek), 29591 (GLRI NY Area 1), and 29645 (WI One Map), all with IMAGE_YR=2020 in the saved official metadata query. They are convenience regions selected for contemporary reference coverage and contrasting landscapes, not a probability sample of US wetlands. They will not be ranked. Differences in mapping conventions, habitat types and within-year timing accompany any regional comparison.

Use 16 non-overlapping 2.56×2.56 km cores per region (256×256 native 10 m pixels), with a 160 m surrounding retrieval buffer. Generate eligible centers on a fixed 0.06-degree lon/lat grid within each project, requiring the entire buffered square to fall inside the project geometry. Use seed 1729 to select 16 centers per project; centers separated at least 5 km. Selection uses only geometry, source coverage and predictor availability, never model outcomes. Preserve a reserve ordering of 16 additional centers per region. Use a reserve only for technical missing-data/coverage failure under the rule below, logging the excluded center and reason. Do not replace an empty/non-wetland block because it has no interesting outcome.

Assign 8 training, 4 validation and 4 test cores per region with seed 2718 before outcomes. No core overlaps and no train/test pixel sharing. Exclude the Minnesota pilot location, which is outside these four projects anyway. The analysis population is mapped patches in the selected cores. It does not estimate national wetland acreage or prevalence.

## Input construction and quality rules

Retrieve complete inventory polygons intersecting each buffered window, preserving source attributes only for habitat codes, IDs and area; no ownership or personal data. Palustrine (code P) is positive. Other NWI aquatic classes (E/L/M/R) are excluded from upland negatives and reported separately. Union touching palustrine sub-polygons before defining patches; subtype boundaries are not separate wetlands. Include for object evaluation only patches wholly inside the core, with vector area ≥0.2 ha and at least one native-grid center pixel. Main small bin is 0.2–1 ha; medium 1–10 ha; large ≥10 ha. Report all boundary-crossing, sub-MMU, zero-pixel, merging and no-interior cases. Objects are mapped patches, not asserted hydrologically independent basins.

Rasterize polygon center inclusion on the AEF grid, preserving object IDs. Store vector areas and rasterized areas. Evaluate patch coverage as the fraction of valid reference-patch pixels predicted positive; recovered means coverage ≥50%. Also report any-overlap and ≥75% coverage as sensitivity analyses. Isolation stratum: nearest other mapped palustrine patch at least 50 m away, using buffered geometry; cap search at the buffer to avoid pretending to know far-away neighbors.

For optical predictors, use three seasonal windows (April–May, June–July, August–September 2020). In each season choose up to two scenes covering the core, by lowest scene cloud fraction, breaking ties by temporal distance from season midpoint and then scene ID. Prefer a single UTM tile covering the buffered core. Use bands blue, green, red, NIR, red-edge1, red-edge2, SWIR1 and SWIR2 plus NDVI and MNDWI. Mask scene-classification cloud/shadow/snow/no-data classes, apply documented reflectance scale/offset, reproject to the AEF grid (bilinear reflectance, nearest categorical mask), and take the clear-pixel median within each season. Do not interpret scene cloud percentage as local clear coverage. Save the per-scene clipped arrays and masks so feature computation can be reproduced offline. A common valid-pixel mask is used for all representations.

A core is a technical coverage failure only if less than 90% of its core pixels have valid embeddings and valid optical values in at least two seasons. Missing values in the remaining season are filled from that pixel's other seasons, accompanied by missing-season indicator features. Log all missingness and imputation. No outcome-based exclusions. If fewer than eight usable cores in any region or fewer than 200 eligible small patches overall remain, do not replace the question: report the inadequacy and limit inference.

Representations: (1) AEF decoded 64-vector, (2) seasonal optical features/indices, (3) optical features plus local Gaussian contextual means at 1- and 2-pixel sigma, as a conventional context control. A hybrid AEF+optical representation is a planned secondary check if useful to distinguish complementary information. The AEF versus optical comparison does not isolate architectural context because their input sources and pretraining differ.

## Sampling policies and comparators

All policies use only training geography. The same selected positions within a seed/budget/policy are used for all final representations and decoders. All labelled positions, including proposal initialization, count toward the budget; repeated positions are not extra labels. Training pools use the common valid mask.

1. **Area sampling:** half positive and half reference-upland positions, sampled without replacement from their pixel pools. This represents equal-class area allocation, not natural-prevalence training.
2. **Homogeneous interior:** the same class counts, sampled at least 20 m from a mapped wetland/non-wetland boundary. Eligibility loss by size is reported, not presented as an unexpected finding. If a budget cannot be filled uniquely, mark that arm unavailable rather than silently duplicate labels or reduce only that arm.
3. **Oracle object allocation:** half positive positions, obtained by first selecting a mapped training patch uniformly and then an eligible pixel uniformly; half reference-upland area positions. Exclude duplicate pixel selections. The full training polygon frame is an explicit information advantage. This is a conditional allocation result, not proof of cheap label acquisition.
4. **Imagery proposal allocation:** spend half the total budget on the same area-sampled initialization used by the uncertainty control. Fit a 100-tree optical-only proposal forest using those labels. Predict only training cores, threshold at 0.5, identify connected components with at least four pixels, and select the remaining positions by uniform candidate component then uniform pixel, excluding already labelled positions. No reference labels are used to choose or filter the second-stage positions. If candidate positions are insufficient, fill from unlabeled area positions and report the count. All acquired second-stage labels count, including negative labels; achieved class counts may differ and must be reported.
5. **Uncertainty allocation:** the same initialization/proposal model, then choose positions by descending predictive entropy with a minimum 30 m separation among additional positions. Fill shortfall by unlabeled area sampling, counting and reporting it. This is a stronger practical active-sampling comparator, not a claim of a new active-learning algorithm.

Final RF: 300 trees, max_features='sqrt', min_samples_leaf=5, class_weight='balanced', fixed seed, at most two worker threads. Logistic regression: standardize using training-sample statistics only, C=1, class_weight='balanced', max_iter=2000. No test-driven hyperparameter selection. The proposal forest's initialization is shared and all its outputs saved. Full validation inventory is available for scientific threshold assessment; it is not included in the reported **training**-label budget. No claim about total annotation labour is made.

Conventional smoothness controls: apply Gaussian sigma 1 and 2 pixels to final optical RF probability maps, without changing the predictor-training samples. Re-evaluate at the same commission-area operating points. Do not assume matching edge density means matching information. Report adjacent-pixel disagreement/edge density for appearance, not success. Do not remove small predicted objects as a hidden postprocessing step.

## Evaluation, comparisons, uncertainty and trivial cases

Primary score: mean across regions of small-patch recovery at a standardized 5% reference-upland pixel false-positive rate, using exact held-out prediction quantiles. This is an evaluation operating point selected with held-out labels, **not a deployable threshold or a measured labour budget**. Use strict probability > threshold to handle ties; report achieved FPR and tie/score-resolution effects. Also report standardized FPR targets 1% and 10%, all-pixel wetland producer's/user's accuracy, IoU, balanced accuracy, and PR area. Plot patch coverage by vector size and isolation; do not let large regions dominate region-average claims silently.

Planned deployment check: choose each threshold on validation geography to target 5% upland FPR, freeze it, and evaluate patch recovery and achieved FPR on the untouched test geography. A standardized-score benefit that disappears under this check cannot support a deployment improvement claim. Report reference-disagreement area and predicted-component counts as separate workload proxies.

Primary contrast H1 uses the mean over five training seeds and the RF decoder at 2,000 labels. Use paired, region-stratified block bootstrap (2,000 replicates, seed 20261027) and resample training seeds to summarize uncertainty. Thresholds are held fixed within this primary block-bootstrap summary; label its intervals as conditional on the evaluated operating thresholds and reference maps. Re-estimate operating thresholds in a planned sensitivity bootstrap if feasible. No significance claim based on treating pixels or patches as independent samples. Regions are convenience cases, so intervals do not establish national generality.

Count and publish: empty-positive cores; patches with no grid-center representation; patches lacking 20 m interiors; boundary-truncated patches; observations shared between sampling policies; identical probability maps/decisions; regions with no eligible patches in a size bin; all-positive/all-negative trivial predictions; proposal-frame misses and fallback labels; actual class counts; achieved FPR and scene coverage. These counts accompany the main results and abstract when they change the interpretation. Formula-derived eligibility limits are design facts, not experimental discoveries.

Planned generalization/alternative explanations: repeat at budgets 500/8,000; logistic decoder; optical contextual means; probability smoothing; hybrid representation; boundary tolerance 0/10/20 m; any-overlap/50%/75% patch coverage; interior-only pixel scoring; reference class/habitat strata; and leave-one-region-out transfer with all thresholds chosen in the other regions. These are the same question's boundary conditions, not unrelated extensions. Execute additional stages in explicit batches with saved configurations, retaining negative/failure outcomes.

## Compute, records, timeline and stopping

No main experiment uses an AI API or the session's text outputs as experimental labels. The one critic was selection assistance; its original response and usage remain preserved. No other AI research assistant or subagent will be called.

Use local Python environment only. Maximum two experiment processes, each controlled by code/run_process.py with timeout ≤1,800 s. Retrieval/model batches may be sequentially resumed from completed per-core/per-fit files; no detached resident process. Every batch stores plan commit, code commit, input hashes, command, times, exit code and stdout/stderr. New or changed metrics/exclusions/hypotheses require a new plan version and are exploratory relative to v1.

Target 64 usable cores; preserve technical reserve ordering. Stop source retrieval on throttling, access restrictions, provider billing requirements or 8 GiB directory use; do not bypass. Reduce the number of completed cores transparently if necessary. Recompute from bundled clipped inputs and saved prediction arrays without network or AI APIs. Commit at the end of each main batch and preserve successful/failed batches. No Git history rewriting.
