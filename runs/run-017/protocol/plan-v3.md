# Main protocol v3: pre-performance sensitivity definitions

This supplements v1 and v2 without replacing their primary contrasts. It is fixed after input inspection for the first eight cores and before any mapping model has been fit or evaluated. The reason is recorded in pre-model-checks.md: many training components are smaller than the evaluation minimum mapping unit (MMU).

Add the secondary policy `object_mmu`: apply the original oracle policy after excluding training components whose vector area is below 2,000 m². Components need not be contained within a training core; appearances sharing a source polygon are merged as before. A merged component is eligible if its recorded component area reaches the MMU in any appearance. Do not use validation/test objects. Keep the original `object` policy, including its smaller components, as the primary oracle contrast. Report the number of components and positive fitting positions below the MMU under both policies. This sensitivity is pre-performance but additional to v1, and cannot retroactively replace H1.

For the planned 0/10/20 m boundary sensitivity, use a raster approximation: the distance transform to the nearest opposite-class pixel center, with one half pixel (5 m) subtracted, and retain centers at least the requested distance from that boundary. This is an approximation to vector boundary distance, not a legal positional tolerance. The pre-existing vector-eroded 20 m interior masks provide a separate interior-only pixel score. For patch sensitivity report both the number of surviving patch pixels and patches with none; do not count a patch with no surviving pixels as a success. The primary metric uses the original common-valid reference centers, without erosion.

Probability-map smoothing uses normalized Gaussian filtering over finite/common-valid probabilities, sigma 1 or 2 pixels and nearest padding at each core edge. This is an evaluation-only postprocessing control; report its finite-window boundary limitation. It never alters training features or labels.

The original full optical feature set has 33 features (30 seasonal bands/indices plus three missing-season indicators). The context control has 93 (the original 33 plus Gaussian means of the 30 band/index features at each of two scales). All model settings, fitting budgets, five seeds, regions, splits, primary thresholds and bootstrap settings remain unchanged.

Annual NLCD was considered as an additional land-cover-prior control because AEF uses NLCD targets in pretraining. Official USGS documentation identifies its cloud bucket as requester-pays; that route is outside the permitted budget. The official MRLC service page lists a land-cover WMS but not an annual land-cover WCS. No paid retrieval or color-to-class reconstruction is attempted. The planned optical-context and hybrid controls proceed; they cannot resolve pretraining independence, which remains a limitation.
