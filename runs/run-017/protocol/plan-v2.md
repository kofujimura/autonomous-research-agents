# Main experimental protocol v2: pre-model input interpretation

This version retains all v1 questions, hypotheses, main contrasts, metrics, regions, 64 target cores, roles, budgets, repetitions, models and stopping rules. Read plan-v1.md in full; the amendments below are controlling clarifications for feature construction and subsequent modeling. It is fixed after raw retrieval began but before any mapping model was fit or any performance result observed.

Reason: real source metadata exposed south-up embedding grids and a known inconsistency between Sentinel item-level harmonization flags and asset offsets. These are input interpretation issues. The original raw arrays and declared metadata remain unchanged. Source issue/documentation S032 was read in full relevant maintainer passages. No new concern is claimed as this study's discovery.

1. **Embedding orientation:** retain exact native 10 m cells and flip array axes to a common north-up grid where necessary, without interpolation; log original and target transforms. The original E02/E03 failures and subsequent technical correction are retained.
2. **Sentinel radiometry:** scale from asset raster:bands. If earthsearch:boa_offset_applied is true, effective additional offset is zero even if asset offset says -0.1; this avoids double subtraction on harmonized COGs. If explicitly false with processing baseline ≥4, use -1000 DN times scale. With baseline <4, no baseline-4 offset is required. If the available fields cannot determine the rule, stop that input for review rather than invent an offset. Retain both declared and effective offsets and the decision. Verify with raw band quantiles/negative-reflectance counts and a source-data visual alignment check. No map-performance result informs the rule.
3. **Clear pixels:** accept SCL classes 2,4,5,6,7 with positive raw DN in all used bands; cloud/shadow/snow/no-data/saturation categories are masked. The retrieved float32 DN arrays are bilinearly resampled inputs, with SCL resampled by nearest neighbor. Full remote COGs were not downloaded, so the SHA-256 covers bundled clipped/resampled arrays, not the entire remote file.
4. **Inventory geometry:** group intersecting/touching palustrine source polygons into connected components before dissolving, including point contacts. Preserve excluded non-polygon/invalid-geometry counts; repair invalid polygons using the standard make_valid operation, recording its frequency. Primary object coverage is over common-valid center pixels as in v1. Report objects with zero valid pixels separately. In addition to v1's boundary checks, report a pre-model sensitivity restricted to patches with ≥90% common-valid reference pixels; this guards against optical missingness making a patch look easier. This is added before performance results and is not a post-result exclusion in the primary score.
5. **Sampling-frame interpretation:** area-balanced and homogeneous samples also assume that class-labelled candidate positions exist. The experiment compares allocation of fitting positions under this supplied reference/candidate-pool regime. It does not simulate all costs of discovering labelled positions de novo. The imagery-proposal arm uses no object identities or second-stage labels for selection, but its initial class-balanced labels are supplied and counted. Its benefit cannot establish that mapping can start without any labelled candidate pool. “Budget” in all results means number of unique fitting positions, not annotation labour or money.
6. **Geometry reserves:** R04 has only six spacing/geometry-eligible reserves; other regions have sixteen. Do not alter the grid or spacing to manufacture more reserves. All sixteen primary cores are available in every region. If an unreplaced technical coverage failure remains after its reserves are exhausted, keep the missing case and report it.

Raw retrieval batches E04/E05 continue under v1 because their archived DN values/metadata and coverage rule are unchanged. All feature construction/model batches will reference v2. None of these changes is a response to mapping performance, which has not yet been measured. The exact chronology is in events.jsonl and Git.
