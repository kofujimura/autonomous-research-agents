# Version 5 — native-grid co-location diagnostic

This secondary input-quality diagnostic is fixed before main score outcomes have been inspected. It does not replace the primary geographic AlphaEarth mosaic or turn a small diagnostic into a full native-grid performance evaluation. Reason: v1's AlphaEarth input is an unofficial EPSG:4326 mosaic, whereas the original representation is published on native UTM10m grids. Its spatial support and exact sampled vectors may differ.

Select up to8 point-years in each role (target, baseline tree reference/control pool, extra baseline non-tree control) and each calendar year2017–2021 by ascending SHA-256(14014,'native_check',task_id), from the union of v1/v2 task tables. This is at most120 point-years. Selection uses neither readout scores nor raw vector values. Save the sample before retrieval. No sample substitution on failure.

Use the official CC BY4.0 public provider-pays Google bucket and its published GeoParquet index, data/aef-native-index.parquet. The official guide and licence/attribution are already saved. At the exact requested WGS84 coordinate/year, choose a file whose published geometry covers the coordinate, preferring the coordinate's standard UTM zone and then lexicographic path if multiple files remain. Do not search for nearby valid pixels. Transform to the file CRS, select the containing pixel, and read a3x3 native patch; retain nodata. Save raw int8 coefficients, source URL, CRS/transform, requested coordinate, pixel-centre coordinate, library versions, actual timestamps and SHA-256. Use verified TLS and ordinary HTTP range reads. No account, payment, inference or third-party AI is involved.

Each job has a hard1800second timeout, total experiment concurrency<=2, per-request HTTP timeout30seconds and no more than3 attempts for a query. Start with one source file as an access/timing check within the prespecified sample, then group at most64 queries/job only when the measured timing fits. Preserve errors/timeouts and successful partial files, reusing saved data. Original storage8.5GiB practical stop,17:00UTC retrieval stop and first-draft deadline remain unchanged.

Decode and normalize exactly as in v1. Compare the geographic-mosaic centre vector with the native containing-pixel vector by cosine similarity, raw coefficient equality and requested-to-pixel-centre distance. Compare normalized3x3 means separately, requiring all nine valid pixels. Report missingness and min/median/5th-percentile/max agreement overall and by role/year; latitude quartiles are a prespecified geographic-support diagnostic. Geodesic distance between the two selected pixel centres is also reported. The footprints differ: native3x3 is approximately30x30m, geographic3x3 has latitude-dependent width.

These comparisons assess input co-location/representation agreement, not correctness of cover labels, ecological validity, or equality of full classification operating points on native data. Even high pointwise agreement cannot prove that small threshold effects are unchanged. Material disagreement must be retained and limit interpretation of AlphaEarth results to the sampled mosaic. Never attribute a difference between embedding systems solely to their encoders without ruling out their different input-processing paths. This diagnostic is secondary and pre-analysis; any additional performance test motivated by its results needs a new versioned plan and an exploratory label.
