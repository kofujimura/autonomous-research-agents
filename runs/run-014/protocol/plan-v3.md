# Version 3 — retrieval scheduling amendment only

Fixed before launching the changed jobs, with no main embedding score outcomes inspected. Versions 1 and 2, their sampling and all scientific methods remain unchanged. Actual completed 64-point-year retrieval jobs took about 99–102 seconds for AlphaEarth and 130–156 seconds for TESSERA, with zero failed tasks in the first three jobs of each provider. These timings justify grouping four consecutive pre-existing 64-task batches into one bounded job (at most 256 point-years), reducing orchestration overhead. The source task order is unchanged. This replaces v1's initial per-process cap of 64 and its decrease-only batch-size rule. It changes neither the 30-minute process timeout nor the two-process concurrency limit, the provider request concurrency of two, retries, stopping time, storage cap or data/method selection.

Each grouped job runs one provider sequentially and has a hard timeout of 1800 seconds through scripts/run_experiment.py. It saves after each point-year and records each task's original batch number. If timing worsens enough that a 256-task job could exceed 30 minutes, reduce the group to fit; incomplete raw files are preserved, and a restart reuses saved successes and never exceeds three attempts per task. Do not launch an expected-overlong job. This is an execution change based solely on access timings, not scientific results. The added v2 control jobs may likewise group their at most 250 tasks under the same limit. Every grouped experiment links to this amendment and the original task CSV; v1/v2 define its scientific purpose.
