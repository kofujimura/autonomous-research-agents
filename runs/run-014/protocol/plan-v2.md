# Version 2 — pre-analysis control-cover and fixed-calendar boundary checks

This additive protocol leaves v1's sample, retrieval order, primary comparisons and primary estimates unchanged. It is fixed while v1 patches are being retrieved, before any main score or predictive outcome has been calculated or inspected. The reason is a full-text comparison with Meroni et al. (2017): their controls resemble the intervention's baseline cover, whereas v1 deliberately uses independent tree-cover controls for both gain and loss. A failure of that particular control rule must not be read as a failure of BACI or normalization generally. These are secondary pre-analysis comparisons, not a replacement study.

## Additional control data

Use the same public-domain LCMAP change CSV. Among 2017–2018 pairs labelled unchanged Grass/forb/herb or unchanged Shrubs, exclude every point in v1 targets or its reference pool and the 10 km pilot exclusion. Select up to 32 Grass and up to 32 Shrub plots by ascending SHA-256(14014, 'extra_control', point_id). Do not inspect or filter future cover. Assign the existing five regions using v1's saved centres in EPSG:5070, without re-fitting regions. Retrieve 3x3 embedding patches for 2017–2021 for each selected control in both v1 representations, with identical public endpoints, licences, raw storage, retry/time/storage limits and source logging. Keep a separate tasks CSV; do not reorder or alter v1 tasks. No API or human experiment is added.

## Secondary comparisons

1. **Baseline-non-tree control adjustment:** for the gain task, subtract the mean start-fixed change of the new baseline Grass/Shrub control pool outside the test region. The reference centroid remains v1's tree-cover R set. This tests the sensitivity of control adjustment to broad initial cover, not ecological matching. Use all valid paired non-tree controls, minimum 8; record the number and initial-cover mixture. Loss continues to use tree-cover controls. An additional exact-initial-class control diagnostic is reported only for groups with at least 8 valid controls of that initial class, with its different availability explicit; it cannot replace the common-case primary comparison. Nearest-8 non-tree controls are a geographic sensitivity when at least 8 valid controls exist outside the region. These controls are baseline-stable over one pair, not known stable throughout the test period.
2. **Frozen-calendar reference:** hold the reference vector at 2017 for all four year-pairs, (u_b-u_a) dot r_2017, and its independent tree-control-adjusted counterpart. This distinguishes fixing a reference within each pair from fixing its calendar year throughout deployment. Use the same R/C allocation and held-out-region exclusions as v1, and require at least 8 valid 2017 reference plots. No future-year label is used to choose the reference.

Use the v1 temporal/spatial fitting, calibration, nominal 10% false-positive threshold, strict flag rule, sensitivity/FPR/J, paired spatial bootstrap and seed 14014. The main secondary analysis uses centre pixels, global references and primary R/C allocation. Patch means and nearest controls are boundary analyses; no test-based choice of method is made. Compare against v1 start-fixed and control-adjusted on exactly common test rows and report when missingness prevents that. The .01 sign and 1e-8 equality checks retain their original descriptive meanings.

## Interpretation and stopping

The additional control pool differs in land-cover composition, so score changes can reflect real cover-dependent responses as well as observation/representation variability. Do not identify “model drift” causally. Success is judged by held-out labelled transitions, not control smoothness. No ecological restoration success follows from these tests. Sampling, reference allocation and comparator limits remain visible. This amendment adds at most 320 point-years per model and can finish comfortably before the v1 retrieval stop time; every process still has a 30-minute timeout and total concurrency stays at two. Preserve incomplete data and original v1 results if any new retrieval fails. Sources, experiment provenance, code commits and hashes follow v1.
